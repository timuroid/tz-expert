## Инструкции
1. Соберите перечень разделов:
   - Используйте реальные заголовки из документа (точное написание).
   - Если заголовков нет, используйте раздел Документ целиком.
   - Не повторяйте одно и то же объяснение в разных местах.
   - Если ошибка однотипно повторяется по документу, вынесите её в общий блок `document_wide` и не дублируйте описание в секциях (в секциях оставляйте только локальные инстансы/ссылки на их ID).
   - Порядок разделов: сортируйте по числовому префиксу заголовка (например, `5.7, 5.8, ... 5.8.16`) лексико-числово; если номера нет — по порядку появления (стабильный фолбэк).

2. Блок `document_wide` (ответственность Шага 2):
   - Агрегируйте инстансы в `document_wide`, если выполняется хотя бы одно из условий:
     (A) «Повторяется много где»: одинаковый паттерн (группируйте по ключу `(error_code + нормализованный what_is_incorrect)`, где нормализация — нижний регистр и удаление номеров пунктов) встречается **в ≥2 разных секциях**;
     (B) «Новый раздел»: целевой раздел из `instances.sections[0]` отсутствует среди заголовков документа (сравнение без регистра, с триммингом пробелов). Пример: `sections=["Приложения"]`, а в документе раздела «Приложения» нет.
   - Для каждой агрегированной группы создавайте **один** элемент `document_wide`:
     • `error_code`: код ошибки;  
     • `instance_ids`: все инстансы, вошедшие в группу;  
     • `what_is_incorrect`: консолидированная формулировка (универсально, без ссылок на пункты);  
     • `how_to_fix`: единая правка на уровне документа; для кейса (B) явно укажите создание/добавление **нового раздела** с названием из `instances.sections[0]` («Создать раздел "<Название>" и …»);  
     • `risk_if_not_fixed`: единый инженерный риск;  
     • `priority`: максимум из приоритетов инстансов группы.  
   - Поле `document_wide` присутствует всегда (может быть пустым массивом).

3. Для каждого раздела сформируйте SectionReport:
   - part: название раздела.
   - errors_present: instance_ids ошибки, которые представлены в разделе исходя из шага 1.
   - issues: по одному на каждый код из errors_present.
     - error_code, 
     - instance_ids: при наличии — ссылались на инстансы шага 1.
     - what_is_incorrect: что исходя instance_ids (шага 1) неправильно в этом разделе по коду (подробно).
     - how_to_fix: как исправить ошибки, представленные в этом разделе по коду.
     - risk_if_not_fixed: инженерные формулировки по сути ошибки.
     - priority: оценка риска (low/medium/high).
   - В секционных `issues` включайте только локальные (неагрегированные в `document_wide`) проблемы. Для агрегированных по п.2 описания **не дублируйте** в секциях.

4. Покрытие инстансов (инвариант):
   - Каждый `instance_id` из шага 1 появляется ровно один раз — либо в `document_wide.instance_ids`, либо в `by_sections[].errors_present` (и, если не агрегирован, сопровождается полным `issues` в этой секции).

## Формат JSON (FinalReportBySections)
- doc_title: название документа.
- by_sections: массив SectionReport.
- document_wide: массив SectionIssue для глобальных проблем (присутствует всегда, допускается `[]`).
